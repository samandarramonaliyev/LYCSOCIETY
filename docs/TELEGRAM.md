# LYC Society Telegram Integration

This document defines the Telegram boundary. The implementation must verify current Bot API behavior and library support during Phase 5; the integration must not assume permissions that Telegram has not granted.

Official references:

- [Telegram Mini Apps](https://core.telegram.org/bots/webapps)
- [Telegram Mini App data validation](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app)
- [Telegram Bot API](https://core.telegram.org/bots/api)
- [Telegram invite links and join requests](https://core.telegram.org/bots/api#createchatinvitelink)

## 1. Launch and authentication

Use the bot’s menu button or Main Mini App configuration to launch the React Mini App. The Mini App loads Telegram’s WebApp script and sends the raw `Telegram.WebApp.initData` to the backend login endpoint.

Telegram’s documentation states that `initData` is the value intended for server validation and that `initDataUnsafe` must not be trusted. The backend must implement the documented HMAC-SHA-256 data-check-string procedure, validate freshness, and then create the application session. The frontend must never send a Telegram ID as an alternative credential.

Phase 2 sends the raw `initData` string as `init_data` to `POST /api/v1/auth/telegram/`. The backend parses the query-string fields, derives the Web App secret from the configured bot token with Telegram's HMAC-SHA-256 procedure, compares the signed hash in constant time, checks a configurable `auth_date` freshness window, and rejects recently used signed hashes for that window. It then creates or updates the account's safe Telegram display metadata and establishes a rotated Django server-side session. The signed Telegram identity only authenticates the application account; `POST /api/v1/verification/claim/` performs the separate Phase 2 roster match. It is not a bot callback or a Telegram group integration feature.

Bot onboarding should provide `/start`, an app-open action, verification guidance, and a fallback message when the user has not completed verification. Users must start the bot before the product relies on direct private messages; notification delivery failures are recorded and surfaced safely.

## 2. Bot process and webhook

Use the same repository/domain services for the bot and the API. The Telegram adapter may run as a separate process for operational isolation, but it is not a separate product service or database.

- Production: HTTPS webhook endpoint with Telegram’s secret-token verification and an explicit `allowed_updates` list.
- Development: long polling is acceptable.
- Handle duplicate updates idempotently using Telegram update IDs and action/request state.
- Parse callback data and commands as untrusted input.
- Keep callback payloads short and opaque; never include PII, secrets, or invite links.

Expected update categories for MVP include private messages/commands, callback queries, `chat_join_request`, and `my_chat_member`; add `chat_member` only if the deployment needs reconciliation and the bot is configured to receive it.

## 3. Owner actions from Telegram

When a join request is created, the notification service can enqueue a bot message to the club owner with student display information and Accept/Decline buttons.

The callback payload contains an opaque request/action reference. The bot adapter maps `callback_query.from.id` to the application user and calls the normal join-request service. The service rechecks that:

- the Telegram user is still the club owner or authorized administrator;
- the request is still pending;
- the requester and club remain in valid state;
- membership limits still allow acceptance.

Repeated button presses return an idempotent current-state response and do not create duplicate memberships or notifications.

## 4. Group-link setup

Recommended MVP setup:

1. The verified club owner starts setup in the Mini App.
2. The backend creates a short-lived, single-use setup token bound to the club and owner.
3. The owner adds the bot to the intended private group/supergroup as an administrator with the minimum required rights.
4. The owner sends `/connect <token>` in that group.
5. The bot receives the command and obtains the chat ID from the Telegram update, not from an ordinary browser request.
6. The adapter calls Bot API methods such as `getChat`/`getChatMember` to verify the group and bot capabilities, then stores the link only if the owner and club are still authorized.
7. The bot creates or confirms a bot-owned invite link configured with `creates_join_request=true` and stores it encrypted.

Telegram documents that bots cannot use invite links generated by other administrators, and that creating/revoking links requires the bot to be an administrator with appropriate rights. The owner must therefore generate the integration link through the bot, or the feature must show a degraded/unavailable state.

## 5. Approved-member group access

Do not expose a permanent unrestricted group link. The recommended flow is:

1. An active club member requests Telegram access from the Mini App.
2. The backend returns the protected bot-generated join-request link only to that active member.
3. The user requests to join in Telegram.
4. The bot receives `chat_join_request` and maps the Telegram user ID to the application user.
5. The bot approves only if the chat is linked to the club and the application membership is currently active; otherwise it declines or leaves the request pending for staff review.

Telegram documents that `chat_join_request` updates require the bot’s `can_invite_users` administrator right, and that approving/declining requests requires that same right. Link forwarding therefore does not bypass the application membership check, although the bot cannot prevent a user from sharing a link before the join request is evaluated.

On membership removal, deny future requests immediately. If automatic removal of existing Telegram members is required, the bot also needs the appropriate restriction/removal permission; otherwise mark the integration as capability-limited and require an owner/admin action in Telegram.

## 6. Meetings and announcements

The application stores meetings and announcements first. The notification service creates in-app notifications and queues Telegram messages based on recipient preferences. Telegram sends are best effort with retry, deduplication, and failure tracking.

Do not send full roster data or private moderation details in group messages. Prefer concise content with a deep link back to the Mini App when the recipient can be authorized there.

Meeting reminders are a scheduled outbox job and must be idempotent. A reminder is not sent after a meeting is cancelled or a user’s membership becomes inactive.

## 7. Permission and failure matrix

| Operation | Needed capability | Failure behavior |
|---|---|---|
| Send private notification | User has an available bot chat/permission | Keep in-app notification; record Telegram delivery failure |
| Receive group join requests | Bot admin with `can_invite_users` | Group integration cannot provide gated access; show degraded state |
| Create/revoke bot invite link | Bot admin with appropriate invite rights | Do not expose a user-supplied link as trusted; ask owner to fix setup |
| Approve/decline group join request | Bot admin with `can_invite_users` | Leave domain membership authoritative and surface integration error |
| Remove existing Telegram member | Appropriate restriction rights | Deny future access; surface that automatic removal is unavailable |
| Read another member’s status | Bot admin may be required | Treat inability to verify as deny, never as allow |

## 8. Security and privacy rules

- Keep bot token and webhook secret out of source control.
- Validate webhook secret and sanitize every update.
- Never trust callback data without looking up the server-side action and rechecking authorization.
- Never log raw `initData`, callback payloads containing identifiers, invite links, or bot API credentials.
- Treat chat IDs and invite links as sensitive integration data.
- Use link rotation/disconnection when a group is compromised or a club is archived.
- Do not promise Telegram actions that depend on permissions the bot does not have.
